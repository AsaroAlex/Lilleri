# Merchant identity and owned taxonomy

This local implementation extends E07/E08. It does not establish coverage of real Italian banks, a calibrated merchant model, counsel approval of the catalogue, or completion of those epics.

`merchant-normalizer-v1` retains the exact source description and merchant name. It produces a separate comparison key and explicit provenance. The local `generic-it-v1` patterns recognise delimited POS/card descriptions and explicitly named PayPal/SumUp/Nexi/Stripe intermediaries. A bare intermediary, unknown pattern, or conflicting provider/descriptor evidence does not invent a merchant. Unsupported existing source text produces `unknown` with the fixed `unsupported_source_text` evidence; it remains readable/exportable without changing the source. Alias writer validation remains strict.

The small original `merchant-dictionary-local-v1` seed has stable global identities, including documented spelling variants. A profile's explicit alias has an independent `merchant:private:<uuid>` identity and revision. Rename, archive and undo preserve that identity. The source `merchantKey`, amount and description are never rewritten. Recurring grouping consumes the resolved identity separately from the display name. Conflicting aliases abstain. Rules Only disables global dictionary resolution while keeping explicit profile decisions. Quiet/private and hidden-category exclusions remove identity, labels, keys and evidence from proposals; they do not remove the owner's source ledger or rights export.

`italian-payment-hints-v1` recognises bounded local keyword hints for F24, PagoPA/CBILL, MAV/RAV, bills, direct debits, explicitly declared wallet top-ups, cash withdrawal, card settlement, salary and pension. Conflicting hints or structural kinds abstain. These are inspectable hints rather than a verified CBI/ISO resolver, measured kind accuracy, or a command to change ledger kind.

## Owned categories and decisions

The first local canonical version has 15 non-selectable parents with default children and 72 selectable leaves. All original 51 codes and labels remain; 21 additive leaves carry `localProposal: true`. The catalogue has Italian and English labels, flow axes, stable codes, quiet-set flags and deterministic hierarchy validation. The 11 existing operational category IDs remain stable. `canonicalCategoryId()` maps conservatively into them and otherwise returns `uncategorised`.

Owned categories support create, rename, nesting, icon, explicit order, hiding, and many-to-one canonical meaning. There is no commercial category limit. Assignments preserve the canonical code, taxonomy version, category revision and exact label when chosen; later renames do not rewrite historical labels. Archive/merge requires an owned preview and captured revision; used categories require a compatible destination, active child categories must move first, and historical quiet choices stay quiet. Undo restores the original assignment snapshots within 30 days and refuses to overwrite later decisions. A pure catalogue migration preview also detects missing/deprecated leaf redirects while preserving historical labels and unresolved choices.

The persisted migration operates on the owned assignment store. Existing operational rules/feedback keep their IDs and text. Broader migrations for future canonical rule references, watchlists and baselines still require those modules and explicit coverage; they are not claimed from assignment-only evidence.

## Persistence and boundaries

Frozen migration `0024_merchant_taxonomy.sql` creates current alias/category/assignment rows and three append-only audit streams. Its SHA-256 is `f348c59f684242a1f57c4e37d40085f1f7dfbca3262667ab83fd889c6c03551d`. Labels, normalized alias keys and event snapshots use the existing profile envelope encryption. Profile-bound blind indexes support lookup. Composite ownership references, forced RLS and immutable history triggers also cover source/profile cascades. All writes serialize through the owned profile row, capture one clock instant, check revisions and reject backwards mutation clocks. Preview fingerprints include actual source revisions, rules, assignments, categories, aliases and privacy flag revisions, including an ABA change that returns to the same visible flags.

`GET /v1/merchants` has a complete strict response DTO. Merchant preview/apply/archive/undo and category create/edit/assign/migration-preview/migrate/undo use server-resolved identity; bodies cannot select another profile. Public impact IDs include visible transactions only, without hidden counts. The owner export includes all encrypted-at-rest histories after decryption, including quiet/private decisions. Its separate strict JSON Schema convertible DTO and semantic validator check scope, transaction/account references, clocks, contiguous audit revisions and historical label/code snapshots. Missing historical source references remain invalid unless the caller supplies the separately authenticated source-erasure receipt map, with exact profile/account/connection scope and event time before erasure. Current assignments continue to require actual ledger rows; absence alone is insufficient. Historical migration assignment events may have cascaded only for an authentically attested erased subject.

The mobile panel uses the profile ICU catalogue, exact money formatting, immediate profile/ledger/request epoch fences, explicit preview confirmation, and no replay after stale writes. Headings have levels 2/3, controls have accessible states and at least 48px targets. The browser helper must run only on a disposable synthetic archive with an exclusive writer slot. It restores privacy and locale; the deliberate synthetic decision audit remains.
