# Bounded XLSX imports

The local importer accepts XLSX in the web file picker, with an explicit worksheet, header row, number convention, date convention and column mapping. Existing account mappings can be reused. Preview, stale-revision fencing, duplicate acknowledgement, command receipts and exact manual balance updates use the same reviewed path as mapped CSV. Native share-sheet intake and verified bank templates remain separate work.

`read-excel-file` is pinned to 9.3.10 (MIT). Before it reads XML, a server-only preflight checks the ZIP central/local directory, disjoint byte ranges, supported compression methods, CRC and actual inflated sizes. `XLSX_IMPORT_LIMITS` is the authoritative typed limit object: 512 KiB compressed, 4 MiB total inflated, 2 MiB per entry, 64 entries, 8 worksheets, 1,100 physical rows, 64 columns and header rows 1–100. The reused CSV normalizer additionally limits selected, nonblank data to 1,000 rows and its in-memory text projection to 256 KiB. Requests are bounded before base64 decoding; inflation has an independent hard cap.

The supported OOXML subset excludes encrypted ZIP entries, ZIP64, duplicate/unsafe paths, unknown binary parts, macros, embeddings, external relationships, DTD/entities, formulas, merged cells, hyperlinks, protections and ambiguous duplicate cell references. Every entry and worksheet is checked, including unselected sheets. Percentage, scientific, fractional and scaled numeric display formats are refused. This conservative subset can refuse otherwise valid Excel files; exporting a simple value-only sheet as CSV remains available.

Numeric XML tokens are parsed into tagged decimal strings, never JavaScript numbers. Numeric amount cells use the locale-independent XML decimal point, while text amount cells use the explicitly selected Italian or British convention. Scientific notation, unsupported numeric tokens and fractional minor units are rejected rather than rounded. Original numeric tokens survive in encrypted source observations. Date-typed and Excel serial-date cells are currently refused; dates must be text in the selected format. No timezone or calendar is inferred from workbook formatting.

`POST /v1/imports/mapped/workbook` takes `{base64}` for sheet discovery, then `{base64, sheet, headerRow}` for header inspection. It does not select a worksheet or header automatically. Existing preview/commit routes accept exactly one of `csv` or `xlsx: {base64, sheet, headerRow}`, alongside exactly one inline mapping or mapping ID. Error responses contain codes and row/column coordinates, without echoed financial cells.

The original workbook is transient: it is not placed in raw-payload storage, logs, command receipts or exports. The accepted snapshot preserves only mapped source cells and workbook origin metadata. The original workbook SHA-256, worksheet, header row and original physical worksheet row are permanent append-only provenance under migration 0027; booking and value dates remain distinct. Internal blank rows are skipped without compacting source row numbers. Original bytes plus the explicit worksheet/header selection determine generated identities and preview revisions. Identical worksheets therefore remain distinct. Regenerated workbooks with different original bytes require review; external source IDs remain compatible with the canonical CSV importer. A hash identifies a file, and does not verify bank coverage or source authenticity.

Owned JSON and ZIP exports retain permanent workbook origin after encrypted raw-payload expiry. Legacy CSV origins retain their existing export shape. Repeating an accepted command uses its existing receipt; editing a file, worksheet, header, locale or mapping requires a fresh preview and gesture.

Validation uses synthetic workbooks, including unsafe XML/ZIP variants, decimal values above JavaScript's safe-integer range, internal blank rows and multiline cells. The actual browser helper is `tools/xlsx-import-ui-smoke.cjs`; use an isolated synthetic demo archive and one writer at a time.
